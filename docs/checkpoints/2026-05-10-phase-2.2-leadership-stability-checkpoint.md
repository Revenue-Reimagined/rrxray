## What this phase shipped

**Primary deliverables:**

- `leadership_stability` collector — first Section B signal. Press-release search via `FirecrawlClient.search()`, LinkedIn current C-suite snippet search (7 per-role queries), founder tenure inference (`/about` regex → Wayback fallback). Press URL deep-scrape (full-page mode) extracts `occurred_at` dates. Returns `name_registrations` for pipeline-side anonymizer registration.
- `observed_stability_trajectory` Section B synthesizer (NEW) — pre-aggregates `LeadershipStabilityData` into name-free `StabilityAggregates` (counts, derived `seat_change_ages_months`, current incumbents, founder presence, collector findings). Hardcoded to Opus 4.7 (Section A stays on Sonnet via ctx.config.model). Voice-processing pattern matches `observed_gtm_motion`.
- `GeminiClient` (NEW) at `rrxray/services/gemini_client.py` — sibling to AnthropicClient; no provider abstraction layer (deferred to Phase 3).
- `extraction` module at `rrxray/services/extraction.py` — duck-typed `LLMExtractor` interface with `HaikuExtractor` + `GeminiFlashExtractor` + `make_extractor()` factory. CLI flag `--extractor=haiku|gemini-flash` (Haiku default).
- `LeadershipStabilityData` schemas at `rrxray/schemas/leadership_stability.py` — `ExecChange` (with `occurred_at: date | None`), `CurrentIncumbent`, `FounderTenure`, `NameRegistration`, plus `RoleCanonical` and `ExecAction`.
- Role + action catalog at `rrxray/collectors/_leadership_stability_catalog.py` — 7 leadership roles, 3 per-action press queries, ROLE_DISPLAY map, FOUNDED_YEAR_PATTERNS.
- Pipeline post-collection anonymizer registration loop (`_register_collector_names`) + extractor wire-up (instantiates GeminiClient when `GEMINI_API_KEY` set, builds extractor via factory).
- Renderer Module Detail Appendix partial (`_leadership_stability_detail.md.jinja`) + Section B narrative block in `report_internal.md.jinja`. Whitelisted press names preserved; LinkedIn-only names anonymized to role descriptors.
- `Config.gemini_api_key` + `Config.extractor_model` fields; new `tests/fixtures/synthetic/leadership_stability/` directory with 3 press fixtures, 3 LinkedIn fixtures, 2 about-page fixtures.

## Known issues / limitations

- **Anthropic credits exhausted mid-validation.** The final two iteration commits (`5f1771d` data-driven seat_change_ages, `56857a8` Opus escalation) were committed but the post-fix Swayable smoke failed with 400 "credit balance too low" before producing fresh narrative output. Ship as-is; next live run after credits are restored will exercise both fixes naturally. Code is correct; tests pass.
- **"9-to-18-month window" framing tic in Sonnet 4.6 narrative.** On the last successful Swayable smoke (2026-05-09), the synthesizer kept describing a 40-month-old change as "9-to-18 months ago" — even with explicit prompt instructions and pre-computed `seat_change_ages_months: 40` in the aggregates. Iteration #3.5 (Opus 4.7) is the expected fix but unvalidated due to credit exhaustion. The 40-month tenure IS correctly stated multiple places in the same narrative; a careful reader self-corrects, but the inaccuracy is real.
- **`occurred_at: None` on LinkedIn-post URLs.** Login-walled; Firecrawl can't extract dates from `linkedin.com/posts/...` URLs even with `only_main_content=False`. Affects ~30-50% of press hits in practice. Limitation accepted; PeopleDataLabs (Phase 2.2-deep candidate) would close this.
- **"Tenure unconfirmed" gaps for non-press incumbents.** When a current incumbent is identified only via LinkedIn snippet (no press hire URL), tenure can't be derived. The narrative correctly punts these as discovery questions, but Dale flagged that "AI should answer these" — addressable via PeopleDataLabs (~$0.20/record × 5-7 records = ~$1/X-Ray).
- **Wayback availability flake.** Same domain produced different `founder_tenure` on consecutive runs (Wayback availability-lookup transient 503s). Graceful degradation works (`source="unknown"` → narrative correctly hedges), but inconsistent. Not a fix worth pursuing for Phase 2.2.
- **Firecrawl search 0 results for some domains.** Latent: even with the v2 bucket fix, queries against very obscure domains can yield zero results. Synthesizer handles this via "Signal Not Recovered" hypothesis. Acceptable.
- **Pre-existing Phase 2.1c bugs visible in renders:** revenue_motion mistakes nav links for job titles (`[other] Product`, `[other] About`, etc.) — flagged for a future Phase 2.1c-fix follow-up, not in Phase 2.2 scope.
- **Synthesizer findings dropped from `data.json` sources aggregation.** Internal-only findings using `rrxray://leadership_stability/...` synthetic source URLs technically live in finding.source but never reach `data.sources` because `LeadershipStabilityData.sources` defaults to `[]`. Cosmetic only; not user-facing.

## Process notes

**Workflow:**

- `superpowers:brainstorming` → spec → Dale review → `superpowers:writing-plans` → plan → `superpowers:subagent-driven-development` → 16 implementer dispatches per CLAUDE.md model matrix (Opus on real-logic, Haiku on mechanical) → `/review` after build complete → 5 review-fix commits → Dale-led quality gate (3 live smokes + 5 iterations) → checkpoint
- This was the first Phase 2.x where `/review` ran after the build and BEFORE the quality gate. Saved memory `feedback_phase_review` to do this on every future phase.

**What worked:**

- Subagent-driven development held up: 16 task dispatches, 1 hallucination on T6 (Haiku claimed success with a fake commit SHA — caught by verification-proof requirement, re-dispatched on Sonnet, landed clean).
- Two-stage review (selectively applied) caught real bugs that tests missed: synthesizer findings dropped at render time, em-dashes in templates, date-anchor logic on Rule 1, hire/promotion filter on tenure heuristic.
- Quality gate caught 9 real bugs across 5 iterations — far more than Phase 2.1b/c precedent of 1-2 iterations. Most surprising: the FirecrawlClient.search v2 bucket bug had been silently broken since Phase 2.1c shipped (revenue_motion's LinkedIn signals were always empty in production but tests mocked the SDK directly so it never showed up).

**What didn't work / surprises:**

- Sonnet 4.6 was unable to follow a strict instruction to use `seat_change_ages_months` over rounded "9-18 months ago" framing, even with both prompt-side and data-side fixes. Escalating to Opus 4.7 is the working pattern; cost goes from ~$0.012 → ~$0.06 per Section B call. Expected-validation pending credits.
- The original spec's `SourceCitation(label="...")` constructor call doesn't match the actual schema (which requires `url: str` + `timestamp: datetime` and has no `label` field). Implementers worked around with synthetic `rrxray://leadership_stability/{label}` URLs. Plan reviewed for this issue going forward; spec writers should validate against actual schemas at brainstorm time.
- Worktree `.env` symlink was a real friction point (cost ~$0.20 in failed runs and ~30 minutes of debugging). Memory saved.

**Token-budget observations:**

- Real-logic implementer dispatches averaged ~50K-80K tokens per dispatch (some up to 200K).
- Quality-gate iteration was the most expensive phase per minute (Opus controller + multiple back-and-forth). Total cost across the phase: ~$3-5 in API spend (mostly Anthropic synthesizer calls + Opus subagents). ~$0.20-0.40 in Firecrawl across all live smokes.
- The Sonnet→Opus synthesizer escalation increases per-X-Ray cost by ~$0.05. Phase 2.3+ should treat that as standard.

- Re-run Swayable + aioapp once after credits restored, confirm the Opus escalation produces clean narrative; if not, revert `56857a8` and accept the Sonnet "9-18 months" tic as a known-limitation.
