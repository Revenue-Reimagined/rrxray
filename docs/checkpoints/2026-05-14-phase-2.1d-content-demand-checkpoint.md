## Known issues / limitations

Surfaced during the final whole-branch review. None are crashes; all are deferred concerns or trade-offs.

- **Important - newsletter false-positive risk.** `_detect_newsletter`'s 200-char "heading near form" heuristic can match an unrelated demo-signup or contact form on the homepage (e.g. "Sign up for a demo" near a form with an email input). Currently any such match classifies as `embedded_form`, which the synthesizer reads as "corporate newsletter shape." Spec intent allows newsletter-shaped intent broadly, so this is borderline-acceptable. Decision point at quality gate: tighten the heuristic (require an explicit "newsletter" / "subscribe" keyword rather than the broader "sign up") or accept the current looseness.
- **Important - scattered imports inside collector.** `rrxray/collectors/content_demand.py` has 9 mid-file import sites with blanket `# noqa: I001` / `# noqa: E402` markers. Artifact of building one-import-per-TDD-task. Ruff is clean because of the noqa markers but a future reader will find it ugly. Defer to a housekeeping commit after merge: consolidate to a single import block at the top of the file.
- **Important - author regex looseness.** `_AUTHOR_RE` (`(?:class=["\'][^"\']*author[^"\']*["\']|>By\s+)([^<]+)`) matches `>By\s+` anywhere in HTML and the `class="...author..."` capture group reads until the next `<`, which means a timestamp or other inline element can leak in. The 80-char cap mitigates but does not eliminate. Defer; flag if a live run produces noisy author values.
- **Minor - `_BLOG_LINK_RE` does not capture nested-element titles.** Anchors that wrap an `<h2>` or `<span>` (rather than plain text) get skipped. Acceptable v1 - most blog index pages render plain anchor text.
- **Minor - `LEAD_MAGNET_CTA_PATTERNS` "state of" under `report` is broad.** Could match "state of the union" or similar phrases in a thought-leadership essay. Acceptable but noted.
