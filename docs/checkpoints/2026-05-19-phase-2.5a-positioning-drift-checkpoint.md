## What this phase shipped

- `positioning_drift` collector — diffs Wayback Machine homepage snapshots at 6-month intervals over 18 months. Deterministic extraction (no LLM): hero headline via H1 regex, sub-headline via first paragraph after H1, primary nav via markdown link parsing. Computes `changed_fields` and `diff_summary` by comparing oldest vs newest snapshot.

## Known issues / limitations

- **Wayback scraping quality varies.** If the Wayback snapshot returns a sparse or JS-heavy page, `_extract_fields` may return all None fields (hero, sub, nav). The collector handles this gracefully (empty snapshot is still recorded, findings note the gap), but users may see snapshots with no extracted content.
- **`MAX_SUBNAV_TEXT_LEN = 40` in catalog is the hardcoded `{1,40}` in `_MD_LINK_RE` but not referenced by name.** Minor DRY gap — the regex has the number baked in. Non-critical; not worth a fix pass.
- **No snapshot for the "current" homepage.** The collector only pulls Wayback snapshots, not the live site. The current hero/nav is visible from `tech_stack` collector's homepage scrape but not wired into positioning_drift. Phase 2.5c synthesizer can cross-reference both.
