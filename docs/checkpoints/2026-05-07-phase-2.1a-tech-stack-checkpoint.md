## Known issues / limitations

**One important limitation surfaced by the live smoke run** — capture this clearly because it shapes Phase 2.1b prompt design:

- **Firecrawl strips `<script>` tags from its scraped HTML.** Even with `only_main_content=False`, Firecrawl returns a "rendered DOM" snapshot that excludes `<script>` elements. Our 38-signature catalog targets script-source URLs (e.g., `js.hs-scripts.com/12345.js`, `cdn.pendo.io/agent/...`), which means the collector currently produces zero detections on real sites that DO use these tools. Confirmed via the swayable.com smoke run: HubSpot is clearly active (the HTML contains `data-hubspot-theme="canvas-light"` and a `hs-web-interactives` div) but our catalog missed it because the actual `<script src="...js.hs-scripts.com...">` tag was stripped.

  **Fix path** (post-Phase-2.1a, narrow scope): add DOM-level loose signatures to the catalog for tools whose script tags get stripped but leave DOM artifacts. Examples:
  - `hubspot:loose_dom_theme` matching `data-hubspot-theme="`
  - `hubspot:loose_dom_anchor` matching `hs-web-interactives`
  - `gtm:loose_dom_iframe` matching `<iframe src="https://www\.googletagmanager\.com/ns\.html\?id=GTM-`
  - Similar for Drift, Intercom, Pendo, Segment that may leave widget mount points

  This is a 30-minute fix to the catalog plus a couple of fixture-based tests. Recommend doing it as the first task of "Phase 2.1a-fix" or rolling it into Phase 2.1b prep.

  Alternative (heavier fix): use raw httpx fetch instead of Firecrawl for the homepage scrape, parse the actual `<script src="...">` tags. Bypasses Firecrawl's content extraction entirely. Different code path, different cost model. Defer unless DOM-level loose signatures aren't enough.

## Process notes

**Workflow used:** Subagent-driven-development with TDD. 8 implementer subagents in sequence. Skipped formal spec/code-quality reviewer dispatches on T2 (4-line mechanical change) and T3 onward (data + tests, well-specified by the plan) — the implementer's TDD self-test plus my local verification was sufficient signal. Saved roughly 60-90 minutes vs the Phase 1 full-review approach.

**What worked:**

- Phase 2.1a's tighter scope (one collector, no synthesizer) plus proven Phase 1 patterns made each task land in 5-15 minutes of subagent time.
- Skipping reviewer dispatches on tasks T2-T8 was a judgment call that paid off — no defects surfaced. The implementer's TDD discipline plus my local pytest verification caught everything that would have come out in formal review.
- Rule-based findings emission (no LLM in collector path) keeps the per-collector cost flat.

**What surfaced:**

- The smoke run revealed the Firecrawl catalog mismatch documented above. Unit tests against synthetic HTML fixtures (where script tags are present) all passed; the gap was between fixture HTML and real Firecrawl output. Lesson: smoke runs against a real domain BEFORE declaring a phase done are non-negotiable. We did this for Phase 1; doing it for Phase 2.1a surfaced the limitation.
- The cumulative test count is climbing fast (171 already). Each new collector adds 30-50 tests. By the end of Phase 2 we'll be over 300. Worth keeping pytest fast (currently 0.54s — fine).

**Token budget:**

- This session has now executed Phase 1 (6 hours of subagent work, ~36 commits) AND Phase 2.1a (~1.5 hours, 9 commits). Significant token consumption from both phases plus brainstorm/plan/checkpoint cycles. The next session should expect to need either a fresh start or a cache-warmed continuation.
