## Known issues / limitations

Surfaced during quality gate. None are crashes; all are deferred concerns.

- **Crunchbase HTML regex parsing may miss rounds on real pages.** The `_parse_crunchbase_html` regex is tuned to the synthetic fixture shape. Real Crunchbase pages render JSON-in-script-tag or React hydration data, not plain HTML tables. In practice, if Crunchbase is not blocked, the current regex will likely miss rounds and fall back to the press path. Crunchbase scraping was always V1/best-effort (Crunchbase pages are increasingly bot-detection hardened). Quality gate confirmed graceful degradation works: if Crunchbase is blocked or returns no rounds, press search fills the gap.
- **Healthicity epoch-date artifact patched but root cause unknown.** The Crunchbase page for healthicity.com returned a round with what appeared to be a date that triggered a `1970-01-01` parse. The epoch-date guard now discards these. The underlying cause (bad date HTML on CB page, or regex matching the wrong element) was not investigated.
- **`SearchResult.description` vs `.snippet` mismatch.** The live firecrawl client returns `SearchResult` objects with a `description` field; the collector's `_extract_press_rounds` falls back to `description` after checking `snippet` via `_get_attr`. Tests mock with plain dicts (which have `snippet`). The fallback ensures live runs work; the test fixture mismatch means snippet coverage in tests is via dicts, not real `SearchResult` objects.
- **`_dedupe_rounds` dedupes by series only** (not by (series, date)). If a company has two distinct Series B rounds (unusual but possible for bridge rounds labeled "Series B-1"), both would collapse to one. Accepted for V1.
